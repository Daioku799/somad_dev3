# AGY Agent Lifecycle & Git Commit Policy

## Overview
本ドキュメントは、Antigravity CLI (agy) による自律開発およびGitコミット運用の原則を規定します。エージェントはこの方針を恒久的なプロジェクト記憶として遵守します。

## 1. 起動時プロトコル (Startup Protocol)
- 起動時に必ず `git status` を実行し、未コミットの変更の有無を確認する。
- `.kiro/specs/` 配下の各仕様書および `system_spec_status.md` を読み込み、最新の進捗状態と未完了タスクを把握する。

## 2. 方針事前確認 ＆ 明示的承認獲得 ＆ こまめなGitコミット規定
- **方針事前提示と明示的承認 (Explicit Approval Requirement)**:
  * タイポ修正や軽微なドキュメント更新等の「軽微な修正」を除き、**コードの書き換え・新規構築・リファクタリング**、または**実行時間のかかるプログラム・シミュレーション・テストの実行**を行う際は、**必ず事前に具体的方針・実行内容・影響範囲・想定時間を提示し、ユーザーから明示的な承認を得てから作業を開始**する。
- **ツール個別承認（Enter押し）の活用と自律実行**: 方針についてユーザーから明示的な承認を得た後は、承認された計画の範囲内でスムーズに連続自動実行する。
- **Atomic Commit (Git書き込みルール)**: 1タスク完了ごと、または単一の論理的変更ごとに必ず検証（テスト等）を通した上で、即座に Git コミットを作成する。
- **コミットメッセージ規約**:
  - `feat(<module>): ...` : 新機能・新スクリプトの追加
  - `fix(<module>): ...` : バグ修正・問題修正
  - `test(<module>): ...` : テストケースの追加・修正
  - `docs(<module>): ...` : ドキュメント・タスク状態の更新
  - `refactor(<module>): ...` : 構造整理・リファクタリング
- **事前検証**: コミット前に必ず該当テストを実行し、パスした証拠（ログ）を確認してからコミットする。

## 3. 終了時プロトコル (Shutdown Protocol)
- `git status` で作業ツリーがクリーンであることを確認する（未コミット変更を残さない）。
- `system_spec_status.md` および該当の `.kiro/specs/$FEATURE/tasks.md` を最新状態に同期する。
- ユーザーに実施作業サマリーおよびコミット履歴のサマリーを出力する。

## 4. 異常発生・クラッシュ復旧プロトコル (Crash & Error Protocol)
- エラー発生時はログおよびスタックトレースを最優先で確認・分析する (`kiro-debug`)。
- 不完全・ビルド不可なコードを作業ツリーに放置せず、必要に応じて `git diff` を確認・調整する。
- エラーの原因、復旧手順、現状をログに残し、ユーザーに明確に報告する。
