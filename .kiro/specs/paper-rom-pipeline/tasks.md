# Implementation Plan

## 1. Foundation: データ契約と出力基盤

- [x] 1.1 データセットの読み取りと分割の確定
  - 計画情報からケース記録（識別子、TSV本数、セル別本数、分割ラベル、偏り指標）を読み取る機能を用意する
  - 各ケースのスナップショットから温度場を読み取り、ゴーストセルを除いた内部領域を列ベクトルとして並べる
  - セル別本数をセル上限で正規化した設計変数を生成する
  - 分割ラベルを指定して該当ケースの添字を返す機能と、TSV本数を指定して該当ケースの添字を返す機能を用意する
  - 内挿テスト用の分割ラベルが、学習・検証・試験のいずれの問い合わせにも含まれないようにする
  - 計画情報のキーが欠けている場合、または温度場の形がケース間で一致しない場合は、該当ケース名を示して読み取りを中止する
  - run 固有のパスを内部に持たず、呼び出し側から受け取る
  - 完了条件: 本番データセットを読み込むと424件のケース記録が返り、分割の内訳が train 300 / validation 42 / test 42 / interp 40 と一致する
  - _Requirements: 1.1, 1.4, 1.5_
  - _Boundary: PipelineData_

- [x] 1.2 結果出力と来歴記録の基盤 (P)
  - 結果表を、対応するケース名を含む列構成で保存する機能を用意する
  - 全水準をまとめた集計と水準ごとの集計を、出力上で区別できるようにする
  - 使用したデータセットの識別子、ケース数、分割の内訳、採用した基底数、補間の設定、乱数の指定を来歴として記録する
  - 全ての出力先を、指定された run ディレクトリ配下の解析結果置き場に限定する
  - 警告を一箇所に集約して保存する機能を用意する
  - 完了条件: 出力先を run ディレクトリ外に指定しようとした場合に拒否され、来歴には識別子・分割内訳・乱数指定が揃って記録される
  - _Requirements: 1.6, 2.6, 3.4, 9.7, 10.1, 10.2, 10.3_
  - _Boundary: PipelineReport_

- [x] 1.3 本 run の実行条件の定義
  - データセットの所在、補助データセットの所在、学習水準、内挿テスト水準、走査する本数の範囲を一箇所に定義する
  - 合格しきい値、相関の上限、予測誤差の許容比、汎化検証の警告倍率、探索のリスタート数、学習曲線のシード数を一箇所に定義する
  - 後続の全ての処理がこの定義のみから条件を受け取り、条件を各自で直書きしないようにする
  - 完了条件: 条件を1箇所書き換えるだけで、別のデータセットに対して同じ解析を実行できる
  - _Requirements: 10.4_
  - _Depends: 1.1, 1.2_

## 2. Core: ROM 構築と精度評価

- [x] 2.1 縮約モデルの構築と保持誤差の評価
  - 学習用に指定された分割のケースのみを用いて基底と補間を構築する
  - 学習に用いていない分割のケースについて、最大温度の平均絶対誤差、二乗平均平方根誤差、最大絶対誤差、および温度場の相対 L2 誤差を算出する
  - 構築した縮約モデルを、後続の処理が再利用できる形で保存する
  - 完了条件: 保持誤差の4指標が出力され、保存した縮約モデルを再読み込みして同じ予測が得られる
  - _Requirements: 1.1, 1.2_
  - _Depends: 1.3_

- [x] 2.2 ベースライン比較
  - 定数モデル、TSV本数のみを用いるモデル、セル別本数の線形和モデルを、縮約モデルと同一の評価データで構築する
  - 4者の予測誤差を同一の指標で並べた比較表を出力する
  - 完了条件: 4者の比較表が出力され、線形和モデルに対する縮約モデルの改善率が算出される
  - _Requirements: 1.3_

- [x] 2.3 配置効果の幅と合格判定
  - TSV本数の水準ごとに、同一本数内で最大温度が取りうる幅を算出する
  - 最大温度の予測誤差と、同一本数内の最大温度の幅とを対比した判定結果を出力する
  - 完了条件: 水準ごとの幅と予測誤差の比が出力され、両者の大小関係が判定として示される
  - _Requirements: 2.1, 2.2_

- [x] 2.4 合格判定しきい値の外部指定と警告
  - 合格判定に用いるしきい値を、既定値に依存せず外部から指定できるようにする
  - 既定のしきい値を、想定される配置効果の幅より小さい値に変更する
  - しきい値が配置効果の幅以上である場合に、判定が意味を持たない旨の警告を返す
  - 既存の判定機能を利用している他の呼び出し箇所が壊れないことを確認する
  - 完了条件: しきい値を幅以上に設定すると警告が返り、幅より小さく設定すると通常の判定が返る
  - _Requirements: 2.3, 2.4_
  - _Boundary: ROMValidator_

- [x] 2.5 最適化性能指標の算出
  - TSV本数の水準ごとに、予測値と実測値の順位相関を算出する
  - 縮約モデルが選んだ設計の最大温度と、候補中の真の最良との差を算出する
  - 全水準をまとめた集計と水準ごとの集計を区別して出力する
  - 完了条件: 水準ごとの順位相関と真の最良との差が出力され、全水準集計との違いが表上で判別できる
  - _Requirements: 2.5, 2.6_

- [ ] 2.6 学習データ量に対する精度の推移
  - 学習用ケースの部分集合を段階的に増やしながら、各段階の予測誤差を共通の評価データで算出する
  - 同一の学習本数に対して複数の異なる部分集合を用い、誤差の代表値とばらつきを算出する
  - 各段階について、最大温度の予測誤差と温度場の相対 L2 誤差の双方を出力する
  - 部分集合の選び方を決める乱数の指定を来歴に記録する
  - 完了条件: 学習本数ごとに複数試行の代表値とばらつきが出力され、同じ指定で再実行すると同一の結果になる
  - _Requirements: 3.1, 3.2, 3.3, 3.4_

## 3. Core: 目的関数候補と第3目的の選定

- [x] 3.1 目的関数候補の型と設計変数由来の候補 (P)
  - 候補指標を、温度場由来か設計変数由来かの区別を持つ共通の形で扱えるようにする
  - 設計変数のみから算出できる偏り指標を候補として実装する
  - 設計変数由来の候補は予測誤差を持たないものとして扱う
  - 完了条件: 設計変数由来の候補が全ケースについて算出され、既存の計画情報中の偏り指標と一致する
  - _Requirements: 4.1_
  - _Boundary: ObjectiveMetrics_
  - _Depends: 1.1_

- [x] 3.2 温度場由来の候補の算出
  - 最大温度が乗る面での面内温度差を算出する
  - 同じ面での面内勾配の最大値を算出する
  - 全ての面について面内温度差を求めた最大値を算出する
  - 三次元勾配の大きさの最大値と平均を算出する
  - 勾配は中心差分で求め、ゴーストセルを除いた内部領域のみで評価する
  - 完了条件: 5種類の候補が全ケースについて算出され、それぞれの値の範囲が水準ごとに出力される
  - _Requirements: 4.1_
  - _Boundary: ObjectiveMetrics_

- [x] 3.3 候補ごとの統計量
  - TSV本数の水準ごとに、各候補と最大温度との順位相関を算出する
  - TSV本数の水準ごとに、各候補が設計によって取りうる幅を算出する
  - 完了条件: 全候補について水準ごとの順位相関と幅が並んだ表が出力される
  - _Requirements: 4.2_
  - _Boundary: ObjectiveMetrics_

- [x] 3.4 候補指標の予測精度の比較
  - 同一の評価ケースについて、実測の温度場から算出した候補の値を求める
  - 同じケースについて、縮約モデルが再構成した温度場から算出した候補の値を求める
  - 両者の絶対誤差と順位相関を算出する
  - 完了条件: 温度場由来の全候補について、実測由来の値と再構成由来の値の誤差が出力される
  - _Requirements: 4.5_
  - _Depends: 2.1, 3.2_

- [x] 3.5 二条件による第3目的の選定
  - 最大温度との順位相関の絶対値が指定した上限を下回ることを、独立性の条件として評価する
  - 候補の予測誤差が、その候補が設計によって取りうる幅に対して指定した比率を下回ることを、予測可能性の条件として評価する
  - 両条件を満たす候補のうち、最大温度との相関が最も低いものを採用する
  - どの温度場由来の候補も条件を満たさない場合、設計変数のみから算出できる偏り指標を採用する
  - 全候補について、独立性・予測可能性・採否・理由を並べた判定結果を出力する
  - 採用した候補を、後続の処理が参照できる形で保存する
  - 完了条件: 判定結果の表が全候補分出力され、採用した候補が中間成果物として保存され、後続処理から読み出せる
  - _Requirements: 4.3, 4.4, 4.6, 4.7_
  - _Depends: 3.3, 3.4_

## 4. Core: TSV本数方向の汎化検証

- [ ] 4.1 水準除外検証
  - 学習用の水準のうち中間の水準を学習から除外し、残る水準のみで縮約モデルを構築する
  - 除外した水準に属するケースの予測誤差を算出する
  - 通常の学習で得られる予測誤差と対比した表を出力する
  - 完了条件: 除外水準の誤差と通常学習の誤差が並んだ表が出力され、両者の比が示される
  - _Requirements: 5.1, 5.2_
  - _Depends: 2.1_

- [ ] 4.2 内挿検証と警告
  - 学習用の全水準で構築した縮約モデルを用いて、内挿テスト用の分割ラベルが付与されたケースの予測誤差を算出する
  - 学習した水準に属するケースの予測誤差と対比した表を出力する
  - 未学習の本数に対する誤差が、学習した本数に対する誤差を指定した倍率以上で上回る場合に、本数を連続に扱う最適化を正当化できない旨の警告を出力する
  - 完了条件: 内挿テスト40件の誤差が学習水準の誤差と並べて出力され、倍率を超える場合に警告が記録される
  - _Requirements: 5.3, 5.4, 5.5_

## 5. Core: 探索と交換関係

- [x] 5.1 多点スタート探索 (P)
  - 設計ベクトルからスカラー値を返す関数のみを受け取り、縮約モデルにも温度場にも依存しない形で探索を実装する
  - 一本をあるセルから別のセルへ移す操作を近傍として、改善が止まるまで降下する
  - 複数の異なる初期設計から探索を開始し、相異なる解の個数を返す
  - 最小化と最大化を同一の実装で扱えるようにする
  - 返される全ての設計が、合計本数の保存とセル上限の制約を満たすことを保証する
  - 完了条件: 既知の目的関数に対して最小値と最大値の双方が得られ、返る設計がすべて制約を満たす
  - _Requirements: 6.2, 6.6_
  - _Boundary: SearchOptimizer_
  - _Depends: 1.3_

- [x] 5.2 TSV本数の走査
  - 指定された各TSV本数について、独立に探索を実行する
  - 学習した水準の範囲外の本数を、探索対象から除外する
  - 各TSV本数について、最良設計・最悪設計・一様配置の目的値と、最良と最悪の差を出力する
  - 完了条件: 指定範囲の各本数について結果が出力され、範囲外の本数が結果に含まれない
  - _Requirements: 6.1, 6.3, 6.4_
  - _Boundary: SearchOptimizer_

- [ ] 5.3 再検証候補の一覧出力
  - 探索で得た最良設計、最悪設計、一様配置、および比較用のランダム設計を候補として集める
  - 各候補の設計変数と縮約モデルによる予測値を、実測による再検証に使える形で出力する
  - 完了条件: 候補一覧が出力され、そこから実測計算の入力を生成できる
  - _Requirements: 6.5_
  - _Depends: 5.2, 3.5_

- [x] 5.4 非劣解集合の算出
  - 最大温度、TSV本数、および選定した第3目的の3者について、他のいずれの設計にも劣らない設計の集合を算出する
  - TSV本数を固定した場合の2目的の非劣解集合を、水準ごとに算出する
  - 目的関数の重み付けを与えずに算出できるようにする
  - 完了条件: 3目的の非劣解集合と水準ごとの2目的非劣解集合が出力され、重みの指定を一切必要としない
  - _Requirements: 7.1, 7.2, 7.5_
  - _Boundary: SearchOptimizer_
  - _Depends: 3.5_

- [ ] 5.5 上限制約下での探索
  - 第3目的に上限値を課した条件下で、最大温度を最小化する設計を求める
  - 上限値の列を外部から受け取り、各上限値について探索を繰り返す
  - 完了条件: 指定した上限値の各点について、制約を満たす設計と目的値が出力される
  - _Requirements: 7.3_
  - _Boundary: SearchOptimizer_
  - _Depends: 5.1, 5.4_

- [ ] 5.6 標本由来と探索由来の区別
  - 標本済み設計から得た非劣解集合と、探索によって得た設計とを、出力上で区別できるようにする
  - 完了条件: 交換関係の出力に由来を示す列が含まれ、両者を分離して取り出せる
  - _Requirements: 7.4_
  - _Depends: 5.4, 5.5_

## 6. Core: 検証結果の集計

- [ ] 6.1 境界条件感度の集計 (P)
  - 補助データセットから、冷却条件および上部界面の扱いごとにケースを分類する
  - 各条件について、最良配置の一様配置に対する改善量、最良と最悪の差、および設計の順位を算出する
  - 完了条件: 条件ごとの改善量・幅・順位が並んだ表が出力され、条件間で順位が変わるか否かが判別できる
  - _Requirements: 8.1_
  - _Boundary: 境界条件感度集計_
  - _Depends: 1.1, 1.2_

- [ ] 6.2 線形性と熱収支の検証 (P)
  - 発熱量を2倍にしたケースと基準ケースの温度上昇の比を算出する
  - 発熱量の総和と冷却面から流出する熱量とを対比した相対誤差を算出する
  - 完了条件: 温度上昇の比と熱収支の相対誤差が数値として出力される
  - _Requirements: 8.2, 8.3_
  - _Boundary: 線形性熱収支集計_
  - _Depends: 1.1, 1.2_

- [ ] 6.3 格子収束の検証
  - 細かい格子での代表設計の実測結果が存在することを前提とし、存在しない場合は欠落として報告する
  - 粗い格子と細かい格子における代表設計の最大温度を対比する
  - 両格子での設計の順位が保存されるか否かを判定する
  - 完了条件: 両格子の最大温度、その差、順位保存の可否が出力される
  - _Requirements: 8.4_

- [ ] 6.4 最適解の実測再検証の集計
  - 縮約モデルの予測値と実測値の差を、候補設計ごとに算出する
  - 各設計が一様配置に対して優れるか否かを判定する
  - 完了条件: 候補ごとの予測値・実測値・差・一様配置比が並んだ表が出力される
  - _Requirements: 8.5_
  - _Depends: 5.3_

- [ ] 6.5 欠落時の部分省略
  - 集計に必要なケースが存在しない場合、欠落したケース名を示す
  - 該当する集計項目のみを省略し、他の項目の集計を継続する
  - 完了条件: 補助データセットの一部を意図的に欠いた状態で実行しても、欠落名が報告され残りの集計が完了する
  - _Requirements: 8.6_
  - _Depends: 6.1, 6.2, 6.3, 6.4_

  - _Requirements: 9.8_
  - _Depends: 7.1, 7.2, 7.3, 7.4_

## 8. Integration: パイプライン全体の接続

- [ ] 8.1 実行ドライバの統合

## Implementation Notes
- 1.1: セル上限とセル数は `DatasetSpec` ではなく計画情報から読む。計画情報が正本のため（design.md を実装に同期済み）
- 1.2: `RunProvenance` は mutable。設定・乱数指定・警告が解析の進行に伴って追記されるため（design.md 同期済み）
- 1.3: 本番424件を一括読み込みするとメモリ約5.9GB（1,728,000セル x 424列 x 8B）。実測で問題なく載る
- 1.3: 補助データセットの計画情報は本番と構造が違う（配列・`N`/`split`欠落）。タスク6.1で正規化アダプタが必要
- 1.3: 計画情報の最上位が辞書でない場合に `MethodError` になる欠陥を修正し、`DatasetLoadError` を返すようにした
- 2.1: 縮約モデルの構築は `PipelineROM` に切り出した。design.md は `build_rom.jl` に置く形だったが、「ドライバは計算ロジックを持たない」という境界方針に合わせ、ドライバは条件注入と出力のみにした
- 2.1: `save_rom` は Julia の型を直列化せず配列と数値のみを書く。`RBFInterpolator` をそのまま保存するとモジュールの読み込み方が変わったとき読めなくなるため
- 2.1: `select_settings` は最良モデルも返す。呼び出し側が `build_rom` を再実行すると 1.7M x 300 の SVD を二度行うことになるため
- 2.1: 本番では基底が60本しか立たない（旧データセットは143本）。RIC 0.9999 と学習300件による。採用24本は旧データセットと同数
- 2.1: 補間設定は旧データセットと独立に選定して同じ値になった（modes=24 eps=0.05 lambda=1e-6）
- 3.2: z は層構成に従い非等間隔（2.5〜22.5 um、9倍の開き）。等間隔とみなすと三次元勾配が最大9倍ずれるため、`GridGeometry` に実座標を持たせた
- 3.2: 勾配はセル単位（計画 §3.12 の定義）ではなく K/m に統一した。dx が全ケース共通なので順位は同一
- 3.2: 本番では最大温度が424件すべて内部 k=10（Silicon1 の発熱面）に乗る。面が切り替わらないため `hot_plane_*` は不連続を持たない
- 3.2: その帰結として `max_plane_dt` は `hot_plane_dt` と424件全件で一致し、候補は実質4種になった。旧データで最有望だった候補は旧BCの PCB 層に由来しており、新BCで消えた
- 3.1: 偏り指標は424件すべてで計画情報の `sum_sq` と一致した（完了条件）
- 3.3: 独立性の上限 0.7 を通るのは `grad3d_max`（|ρ| ≤ 0.303）と `sum_sq`（|ρ| ≤ 0.248）の2つだけ。他の4候補は全て超過する
- 3.3: 第3目的は利用者の決定により `grad3d_max`（三次元勾配の最大）に固定。3.5 は選定ではなく決定の記録として実装する
- 3.3: 3.4 が不合格でも勾配で進める方針（利用者判断）。予測誤差は正直に報告し、「ROMで勾配まで最適化できる」とは主張しない
- 3.4: 勾配の予測は懸念に反して十分だった。grad3d_max は MAE 828 K/m、誤差/幅 0.041（上限 0.2 に対し5倍の余裕）、実測由来とROM由来の順位相関 0.991。24基底のままで足りる
- 3.4: 全6候補が予測可能性を満たした。落ちるのは独立性のほうだけ
- 3.5: 機械的選定の結果も `grad3d_max` で、利用者の決定と一致した。`third_objective_override` は結果を変えていないが、決定の経路を記録するために残す
- 3.5: 退避先 `sum_sq` は独立性・予測可能性とも満たすが、温度場由来の候補が優先されるため不採用。査読で問題になった場合の代替として使える
- 5.1: 目的関数の1回の評価に全温度場（172万セル）を再構成すると、1水準あたり400リスタートで21時間かかり探索が成立しない。最大温度は場全体の最大なので上位2万行（全体の1.16%）に限定でき、86倍速になる。限定と全行の差は holdout 84件で最大 2.27e-13 K

- 5.4: 支配関係の判定は標本済み・探索由来とも縮約モデルの予測値で行う。実測値と混ぜると同じ土俵にならないため。実測値は別列に残す
- 2.2: ROM は cells（配置に線形・17母数）に test で +34.8% 勝つ。ここで負けていたら非線形な代理モデルを作る意味が無かった
