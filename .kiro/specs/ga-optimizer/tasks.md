# Implementation Plan: ga-optimizer

## Tasks

- [ ] 1. Foundation: 型定義と最適化設定の構築
- [x] 1.1 最最適化エンジンで使用するデータ構造の定義
  - 密度マップ `mu`、個体（Individual）、および最適化状態（OptimizationState）の構造体を `Types.jl` に定義
  - 適合度（fitness）や検証ステータスを管理するフィールドの追加
  - 型安全性が確保されたデータ構造が `H2-rom/src/GaOptimizer/Types.jl` に作成されていること
  - _Requirements: 1.1_
- [x] 1.2 最適化パラメータのロード機能の拡張
  - `config-loader` を介して、GAパラメータ（世代数、個体群サイズ、突然変異率、エリート数等）をJSONからロード
  - `OptimizationConfig` 構造体にパラメータが正しくマッピングされること
  - _Requirements: 1.4_

- [ ] 2. Constraint Management: 密度マップ制約修正エンジンの実装
- [x] 2.1 (P) 密度マップの正規化と境界チェックの実装
  - ベクトル `mu` の総和が総TSV本数上限を超えないよう比例スケーリングする関数の作成
  - 各要素 `mu_i` が [0.0, 1.0] の範囲に収まるようクランプ処理を実装
  - テストコードにより、制約違反の個体が有効な範囲に修正されることが確認されていること
  - _Requirements: 2.1, 2.2_
  - _Boundary: ConstraintManager_
- [x] 2.2 (P) 配置禁止領域とセル密度上限の強制適用
  - `forbidden_zones`（配置禁止エリア）に該当するセルの密度を 0 に固定するロジックの実装
  - セルごとの最大密度制約（max_density_per_cell）の適用
  - _Requirements: 2.1_
  - _Boundary: ConstraintManager_
- [x] 2.3 (P) 無効値のガードおよび無効個体の検知・再生成プロセスの実装
  - 入力された `mu` ベクトルに `NaN`、`Inf`、あるいは極端に小さな値（全要素が `1e-9` 未満）が含まれているかを検知するロジックの実装
  - 制約適用（`apply_constraints!`）の前に無効値を検知した場合は、ランダム値で事前リサンプリング（pre-resample）を行ってから制約を適用し、変換エラー（`InexactError`）を回避すること
  - `adjust_constraints!` のループ内で無効個体が検知された場合、有効な個体が得られるまで最大100回再サンプリングを行う仕組みの実装
  - `NaN` や `Inf` を含む入力、あるいは全ゼロマップを渡した際にも、例外を吐くことなく正常に制約を適用して有効な密度マップが出力されることがテストで実証されていること
  - _Requirements: 2.3_
  - _Boundary: ConstraintManager_

- [ ] 3. GA Engine: 最適化ループの構築
- [ ] 3.1 (P) 密度マップ用遺伝的オペレータの実装
  - ベクトル表現に適したブレンド交叉（BLX-α）および突然変異（ガウス突然変異など）の遺伝的オペレータの実装
  - 遺伝操作 of 直後に `ConstraintManager` を自動呼び出し、生成された子が常に物理的制約を満たすよう正規化される仕組みの構築
  - 作成したオペレータが期待通りに親ベクトルから子ベクトルを生成し、かつ制約が満たされていることがテストで確認できること
  - _Requirements: 1.3, 2.2_
  - _Boundary: Engine_
- [ ] 3.2 (P) 適合度評価と選択ロジックの実装
  - ROM評価インターフェースを利用した個体の最高温度の算出と適合度設定の実装
  - トーナメント選択およびエリート保存を組み合わせて次世代個体群を選出する選択機能の実装
  - 個体群の適合度順のソートと、次世代への移行が正しく機能することがテストで実証されていること
  - _Requirements: 1.1, 1.2_
  - _Boundary: Engine_

- [ ] 4. Reliability & FVM: 信頼性管理と再検証の実装
- [ ] 4.1 (P) ROMの外挿検知ロジックの実装
  - 入力された密度マップ `mu` がROMモデルの訓練データ範囲内にあるか（信頼できるか）の判定ロジックの実装
  - 外挿領域と判定された個体に対してログを記録し、適合度にペナルティ（最高温度の増加など）を付与する機能の実装
  - 訓練範囲外のデータに対して外挿フラグが正しく立ち、ペナルティが適用されることがテストで実証されていること
  - _Requirements: 3.1_
  - _Boundary: ReliabilityManager_
- [ ] 4.2 (P) 有望個体に対するFVM自動再検証
  - 最適化における上位個体（エリートなど）に対して、物理ソルバー（FVM）を直接呼び出して厳密な熱解析を実行する機能の実装
  - 物理ソルバーでの結果（最高温度）とROMの予測値を比較し、予測誤差を記録する仕組みの構築
  - エリート個体に対する物理ソルバー解析がクラッシュせずに実行され、結果が適合度計算に反映されることがテストで実証されていること
  - _Requirements: 3.2, 3.3_
  - _Boundary: ReliabilityManager_

- [ ] 5. Integration & Final Validation: システム統合と最終検証フロー
- [ ] 5.1 最適化メインエントリの実装と実行制御
  - 各モジュールを統合し、JSONパラメータおよびROMモデルの読み込みから最適化ループを制御するメイン実行機能の実装
  - 最適化の進行状況（世代ごとの最良適合度など）のコンソール出力と、中間・結果データの永続化（JLD2）の実装
  - 最適化プロセスが正常に開始され、指定された世代数だけ実行されて収束履歴が保存されることが確認できること
  - _Requirements: 1.4_
- [ ] 5.2 最終解の物理モデル生成と検証フローの完遂
  - 最適化完了後、最も優れた密度マップに対して「実TSV座標への展開」および「物理ソルバー（FVM）による最終熱解析」を実行する最終検証フローの実装
  - 解析最高温度、実座標データ、およびROMとFVMの誤差比較を含む検証レポートの出力機能の実装
  - 最良個体に対する最終検証フローが正常に完遂し、期待されるフォーマットでレポートファイルが生成されることが確認できること
  - _Requirements: 4.1, 4.2, 4.3_
