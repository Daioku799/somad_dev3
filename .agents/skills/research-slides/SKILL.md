# 根拠と掲載範囲を固定するスライド作成

最初に `.kiro/steering/agent_policy.md` と `docs/研究AIハーネス_使い方.md` の「スライド」を読む。研究側の読取り権限と指定された新規出力先の書込権限を確認する。別リポジトリへの書込許可を推定しない。

1. 指定された進捗・図・条件だけを読む。既存source-notes.ymlを出典の入口にし、元資料を確認する。文献・ログ・旧テンプレートは追加内容の許可ではない。
2. 主張と留保、対応根拠、図と系列、変換・集計・正規化、軸・単位を一覧にし、構成案を本人へ示す。未指定の追加実験や反例は載せない。既存根拠に矛盾があれば報告し、誤解を招く主張を保留・限定する。
3. 構成案の採用後、作業票のscope.operationsをslidesだけにし、scope.presentationに掲載内容を固定してslides承認を記録する。本人の最新応答と照合し `check --action slides --write <出力ファイル>` を通してから描画する。複数出力は--writeを繰り返す。実行するコマンドがあれば同じ直前checkへ `--command-json '<実際のargv配列>'` を必ず渡して照合する。図が足りなければ構成確認へ戻り、新規FVM・ROM学習・スイープで埋めない。
4. Marpを正本とし、既存図の再利用を初期方式にする。再描画は許可された入力・系列・処理だけで行い、生成スクリプトも参照として束縛する。必要な図だけを新規assetsへ複製し、生データや既存成果物は変更しない。表示用リンクは出力側で完結させる。
5. 実際の描画入力からmanifestを作り、出力ファイルhashとともに `check --action slides --manifest <manifest>` で照合する。承認側のmanifestを実出力としてコピーしない。入力・コード・実画像と全ページを独立レビューする。一致だけで余計な系列がないと断定しない。
6. 重要な図について「何を比較しているか／なぜこの方法か／どこまで言えるか」を本人と確認する。AIの想定問答やレビュー合格を、本人が説明できる証拠にしない。説明できない部分は相談または構成確認へ戻す。根拠の留保を削って説明しやすくしない。
7. 本人が説明可能と確認した応答と、その時点のmanifest hashをpresentation_acceptanceに記録し `check --action present --manifest <manifest>` を行う。それまでは草稿。出力が変われば説明確認は再び必要。

このSkillは内容・出典確認を担当し、数値実験や研究方法の採用は担当しない。使い方のモデル割当を参照し、追加調査の提案を実行許可に読み替えない。
