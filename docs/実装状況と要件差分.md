# 実装状況と要件差分

## 1. 目的

この文書では、`somad_dev3` の現在の実装状況と、`要件定義.md` に記載した目標要件との差分を整理する。

`要件定義.md` はシステム全体として満たすべき仕様を記述し、本書は実装の進捗確認、未実装項目、次に実装すべき項目を管理するために用いる。

## 2. 現在の実装状況

### 2.1 FVMソルバ・モデル構築

- `H2-main-ext` に、JSON設定を読み込み、プリミティブ形状を格子へ割り当て、FVMを実行する基本構成が存在する。
- `ConfigLoader`、`ComponentGenerator`、`ModelBuilder` などの構成があり、解析モデル生成の骨格は実装されている。
- 現在のTSVモデルは、`tsv_config.json` の `manual_coordinates` に基づく個別座標TSVである。
- TSVは円柱プリミティブとしてモデルへ反映される。

### 2.2 スナップショット生成

- `H2-rom` に、FVMスナップショットを生成する仕組みが存在する。
- 現状のサンプリングは、TSV半径と個別TSV座標を設計パラメータとして扱う。
- `SnapshotGenerator/Sampler.jl` では、固定本数のTSVについて、半径と座標をサンプリングする構成になっている。
- `SnapshotGenerator/Runner.jl` では、`tsv_mode = "manual"` と `manual_coordinates` を含む `tsv_config.json` を生成し、`H2-main-ext` のFVMを呼び出す。

### 2.3 ROM・最適化

- POD + RBFによるROM構築本体は、現状では未実装または仕様段階である。
- GAによる密度マップ最適化は、現状では未実装である。
- ROM精度評価、外挿検知、ROM更新処理も、要件としては整理されているが、実装は今後の対象である。

## 3. 要件との差分

### 3.1 TSV表現

要件では、初期実装のTSV表現を密度マップ方式とする。

一方、現在の実装は個別TSV座標方式である。

必要な対応は以下である。

- `tsv_config.json` または追加JSONで、密度マップ設定を読み込めるようにする。
- `tsv_mode = "density"` 相当のモードを追加する。
- 既存の `tsv_mode = "manual"` は、詳細検証用または互換機能として残す。
- 個別TSV座標ではなく、密度ベクトル `mu` をROM用設計パラメータとして保存できるようにする。

### 3.2 密度マップ処理

要件では、TSV密度マップをFVM入力へ変換する必要がある。

現在、密度マップ処理は未実装である。

必要な対応は以下である。

- 密度マップを生成・検証・正規化する処理を追加する。
- 総TSV本数上限、セルごとの密度上限、配置禁止セルを扱えるようにする。
- 密度マップからセルごとの実TSV本数を計算する。
- 密度マップから実TSV座標を展開する。

### 3.3 FVMへの反映

要件では、密度マップから実TSV座標を生成し、FVMの既存TSV円柱モデルへ渡す。

現在の実装では、個別TSV円柱を材料IDとして格子へ割り当てている。

必要な対応は以下である。

- 密度セルから実TSV座標を生成する処理を追加する。
- 生成したTSV座標を `manual_coordinates` 相当の形式へ変換できるようにする。
- TSV半径、最小ピッチ、端部マージン、総TSV本数上限を検証できるようにする。
- 個別TSV円柱モデルを、密度マップから生成した座標でも利用できるようにする。

### 3.4 ROM構築

要件では、密度マップをパラメータ `mu` として、POD + RBF ROMを構築する。

現在、FVMスナップショット生成までは存在するが、ROM構築本体は未実装である。

必要な対応は以下である。

- スナップショット行列を構築する。
- POD基底を生成する。
- 密度ベクトル `mu` からPOD係数を予測するRBFモデルを構築する。
- ROMモデルを保存・読込できるようにする。
- 検証用密度マップに対して、FVM結果とROM結果の誤差を評価する。

### 3.5 GA最適化

要件では、GAが密度マップ個体を生成し、ROMで高速評価する。

現在、GA最適化処理は未実装である。

必要な対応は以下である。

- 密度マップをGA個体として表現する。
- 交叉・突然変異後に、総TSV本数上限やセル上限を満たすように制約修正する。
- ROMにより最高温度 `Tmax` を評価する。
- 有望個体または外挿個体をFVMで検証する。
- 最良密度マップ、温度場、評価履歴を出力する。

## 4. 推奨実装順序

1. 密度マップ設定入力の追加
2. 密度マップ生成・制約処理の追加
3. 密度マップから実TSV座標への展開
4. 展開後TSV座標のピッチ・チップ範囲検証
5. 密度マップサンプリングによるFVMスナップショット生成
6. POD + RBF ROM構築
7. ROM精度評価
8. GAによる密度マップ最適化
9. 有望解のFVM再検証

## 5. 現時点で扱わない項目

以下は初期実装後の拡張対象とする。

- HPWLを含む多目的最適化
- 信号TSVやネットリストを用いた配線長評価
- 個別トランジスタ座標に基づく厳密KOZ評価
- 実TSV座標展開方式の高度化
- `8×8` 以上の高解像度密度マップ
- TT分解を用いた高次元ROM
