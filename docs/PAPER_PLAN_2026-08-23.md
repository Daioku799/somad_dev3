### 2.3 境界条件の診断と修正

### 2.4 対流RHSのバグ発見と修正

- 症状
  - `RHS_convection!` が右辺に `h·A·(T_amb − θ)` を置いていた
  - T_P が対角（`conv_*`）と右辺の両方に現れて二重計上
  - 定常計算では θ が初期値に固定される（nt=1）
  - T_amb = θ_init = 300 なので項が消え、全対流面が実質「外気0 K相当」として振る舞っていた
- 修正
  - `fix_conv_rhs` フラグを追加し、`b += h·area·ta` に変更
  - 6面すべてに適用
- 検証
  - 入力2倍 → 出力ちょうど2.000000倍
  - 4種類の境界条件で場の形が 1e-8 / 2e-9 の精度で一致
- 補足
  - 旧プログラム H2-main-original では x_minus/y_minus/z_minus が `-=`、plus面が `+=` と符号が不統一だった
  - H2-main-ext では6面すべて `+=` に統一済み（h(T_∞−T_P) はスカラーなのでこれが正しい）

### 2.6 ROMとGreen関数の関係整理

- ROM: μ（TSV密度マップ）→ 温度場。POD + RBF。構造空間の代理モデル
- Green関数: 各熱源ブロックを単独で焚いた温度場。熱量空間は線形なので厳密な重ね合わせ
- 重ね合わせ検証: 132配置で相対誤差 3.1e-4（合格）
- 12個のGreen関数があれば、12ブロックの熱量配置は追加FVMなしで全通り評価できる

### 2.8 サンプリング手法

- 現状は Dirichlet サンプリング（LHSではない）
  - 集中度 α を 0.2〜10 の対数一様で振り、一様〜集中の配置を網羅
- **LHSは使えない**
  - μ の定義域は「16セルに整数を配り合計を固定」という制約付きで、箱ではない
  - 標準LHSは simplex 制約で機能しない（CASTRO論文が明言）
  - LHSは N点セットを丸ごと設計する方式なので、後からM点を足すと LHS でなくなる
    （外挿の補強のためにデータを足す運用と相性が悪い）
- **16次元の空間を覆うことは原理的に不可能**（詳細は §3.5）
  - 制約付き空間の space-filling は「次元の呪いにより4次元が実用限界」（CASTRO論文）
- **覆う必要がない**
  - 応答が μ にほぼ線形（17パラメータ線形モデル `cells` が test MAE 0.0957 K、ROMは 0.0765 K）
  - 線形なら必要点数は「空間を覆う数」ではなく「パラメータ数の数倍」。17パラメータに330点は約20倍
- Dirichlet の妥当性には直接の文献がある（Jourdan 2024、§8）
- この問題は統計では **混合物実験計画（mixture design）** と呼ばれる分野に属する

### 2.9 目的関数と多目的化

- Paretoフロント（支配されない設計の集合）で報告する
  - ある設計Aが別の設計Bに対し「全目的で同じか良く、少なくとも1つで厳密に良い」とき AはBを支配する
  - 誰にも支配されない設計の集合がParetoフロント
  - 実データでは330設計中21点が非支配（6.4%）
- 重み付き和はフロント上の1点を選ぶことに相当するので、フロントを出せば重みに依存しない
  - フロントがへこんでいる部分は重み付き和では取れないので、フロントを直接出すほうが取りこぼしがない
- 支配的な（全目的で最良の）設計は存在しない
  - N=48 では case_052 が Tmax 最小だが Σn^2 は最大、case_235 はその逆
  - TSVを固めるほど Tmax は下がるが偏りは増える、という本物の対立がある
- **目的関数は後から変更できる**
  - 温度場と μ から計算するだけなので、追加・変更・削除は全て後決めで可能
  - スナップショット作成前に決めるべきは「何を保存するか」だけ

### 2.10 TSV本数を水準にするか連続にするか

- **ROMは1つ。全水準を混ぜて学習する。分けるのは評価の集計だけ**（詳細は §5.1b）
- 混ぜて学習してもROMは配置を学習できている（N=48固定で Spearman 0.9526）
- 問題は評価の見かけ
  - N を混ぜると、配置を一切見ないモデルでも Spearman 0.88 が出てしまう
  - N を固定すると同じモデルは -0.04 に落ちる（§3.10）
- **学習の水準数と最適化の解像度は別物**
  - FVMは3水準でしか計算しなくても、ROMでNを1本刻みに振れば連続的なParetoフロントが描ける
  - 「Paretoが3本の縦列に見える」問題は起きない
- **TSV本数を目的関数にするのに水準数は関係ない**
  - N = Σμ なので厳密に分かる。予測が要るのは Tmax だけ
  - 「3水準でNを目的にできるか」は「ROMが未学習のNでTmaxを予測できるか」に還元される

### 2.11 目的関数の選定

- 「温度勾配」の定義次第で、目的として機能するかどうかが変わる（§3.12）
- 素朴な Tmax − Tmean は Tmax とほぼ完全に相関するため使えない
  - 平均温度は総発熱と境界条件でほぼ決まり、TSV配置ではほとんど動かない（Tmeanの幅は0.32 K）
- 3目的にすること自体に問題はない
  - `pareto_and_power.jl` は既に3目的（Tmax, N, Σn^2）で動作している
  - 入れ替えるのは3つ目だけ

### 2.12 第3目的の決定と、温度勾配の予測誤差という関門（2026-08-25）

**決定: 第3目的は「三次元勾配の最大」（`grad3d_max`）とする。**

新データ424件で6候補の Tmax との順位相関を測った結果（§3.20）、独立性の上限 0.7 を
通るのは `grad3d_max`（|ρ| ≤ 0.303）と退避先の `Σn^2`（|ρ| ≤ 0.248）の2つだけだった。
温度場由来の候補で残るのは `grad3d_max` のみである。

**ただし、勾配を目的関数にすることには固有の危険がある。**

ROM は温度場を `T ≈ 平均 + Σ aᵢφᵢ` と再構成する。勾配はこれを微分した
`∇T ≈ ∇平均 + Σ aᵢ∇φᵢ` になるが、

- 打ち切って捨てた高次モードは**細かい空間構造（高波数）**を持つ
- **微分はその高波数成分を増幅する**（波数 k の成分は微分で k 倍される）
- したがって温度場の誤差が小さくても、勾配の誤差はそれより大きくなる

本番の ROM は60基底のうち**24基底しか使っていない**（§3.21）。温度場の相対 L2 誤差は
0.0151% だが、勾配の誤差がこれと同程度である保証はない。さらに `grad3d_max` は
**微分した場の最大値**であり、局所的な誤差がそのまま指標の誤差になるため、
候補の中で最も予測が難しい量である。

**判定基準**（タスク 3.4）:

```
勾配の予測誤差 < 設計による変動幅 x 0.2
N=48 なら 20,294 K/m x 0.2 = 4,059 K/m
```

**不合格だった場合の方針（決定済み）: それでも勾配で進める。**

- 予測誤差を表に載せ、正直に報告する
- 「ROM で温度勾配まで最適化できる」とは主張しない
- フロントの形は**傾向を示すもの**として提示し、勾配の絶対値は主張しない
- 退避先の `Σn^2` は独立性を満たすので、査読で問題になった場合の代替として残す

**基底数を増やす選択肢**: 24 → 32/48 基底で勾配誤差を測り直すことは可能（約10分）。
ただし基底を増やすと RBF が過適合して Tmax 精度が落ちる（旧データで114基底が
test MAE 0.457 K まで悪化した実績がある）。**Tmax 精度と勾配精度のどちらを取るかの
交換関係**になるため、両方を測ってから判断する。

### 2.13 平均温度の水準は 3D-IC として妥当か（未決・2026-08-25）

現在の条件での実測（§3.22）:

```
総発熱量 0.384 W、ダイ基準の平均電力密度 38.4 W/cm^2
Tmax     315.7 〜 318.5 K   （上昇 15.7 〜 18.5 K）
Tmean    309.0 〜 309.5 K   （全体）
シリコン層平均               （上昇 9.6 〜 10.2 K）
全体の熱抵抗 R = 44.25 K/W
```

**文献の 3D-IC は接合温度 350〜400 K（上昇 50〜100 K）を報告するのが普通**であり、
本研究の上昇 17 K は**3〜5倍低い**。

原因は境界条件ではなく発熱量である。熱抵抗の内訳は、

- 境界（上面対流）: 4.60 K/W = 全体の **10%**
- 積層内部: 39.6 K/W = 全体の **90%**（樹脂層 λ=1.5 が支配的）

面積で正規化した熱抵抗は 44.25 K/W x 0.0144 cm^2 = **0.637 K·cm^2/W** で、
3D-IC の積層として妥当な範囲にある。つまりモデルの熱抵抗は正しく、
**電力密度が文献の下限側にある**ことが温度水準の低さの理由である
（Tavakkoli 2016 のチップ平均 90 W/cm^2 に対し本研究は 38.4 W/cm^2、2.34倍の差）。

**この問題は線形性によって解決できる。** 実測で確認済み:

```
発熱2倍のとき温度上昇の比 = 2.000128（厳密に2.0）
```

物性値は温度に依存せず、対流も線形なので、`T - T_ambient` は発熱量に**厳密に比例する**。
したがって、

- 設計の**順位は発熱スケールに対して不変**
- 最良・最悪の**相対的な改善率も不変**
- 変わるのは絶対温度だけ

**選択肢:**

| 案 | 内容 | 代償 |
|---|---|---|
| A | **温度上昇 ΔT で報告する**（絶対温度を出さない） | 追加計算ゼロ。査読で「Tj が低い」と言われない |
| B | **発熱を約3倍にスケールして報告**（ΔT 51 K、Tj 351 K = 78°C） | 追加計算ゼロ（線形性より事後スケール可）。ただし電力密度 115 W/cm^2 の根拠が要る |
| C | 現状のまま絶対温度で報告 | 「3D-IC にしては冷たい」という指摘を受ける可能性 |

**未決（D8）。** ただし追加の FVM は不要で、原稿の書き方の選択に留まる。

### 3.10 TSV本数を水準にする根拠

順位相関（Spearman）の比較:

```
                     全水準を混ぜた場合    N=48に固定
本数を数えるだけ          0.8822            -0.0366
ROM                      0.9931             0.9526
```

- N を混ぜると、**配置を一切見ないモデルでも 0.88 の相関が出る**
  - N=24の設計は全部熱く、N=72の設計は全部涼しいため、本数を知るだけで順位のほとんどが当たる
  - この 0.88 は「ROMが配置を理解している」ことを何も証明しない
- N を固定すると、本数だけのモデルは -0.04 に落ち、ROMは 0.95 を保つ
  - **この数字が「ROMは配置を理解している」の証明になる**
- N の効果（36→60 で約3 K）は配置の効果（1.6 K）の2倍あるため、N が自由に動くと配置の議論が埋もれる
- **効果が薄れるのではなく、測れなくなる**
  - 同一Nの設計対が存在しないと「本数を変えずに配置だけで1.6 K」という比較が作れない

### 3.11 Tmax の TSV本数依存性

```
N     平均Tmax [K]     1本あたりの効き
36    352.1618
48    350.5415        36->48: -0.1350 K/本
60    349.1806        48->60: -0.1134 K/本
```

- **厳密には線形ではない**。TSVを増やすほど1本あたりの効きが落ちる（収穫逓減、上に凸）
- 3水準あれば2次曲線が引けるので、この曲がりは捉えられる
- N の効果（36→60 で約3 K）は配置の効果（1.6 K）の約2倍

### 3.12 目的関数候補の独立性

既存の90スナップショット（各水準30件）で、Tmax との順位相関を測った。
**相関が低いほど独立した目的として機能する。**

| 指標 | Spearman(Tmax, ·) | 設計による変動幅 | 判定 |
|---|---|---|---|
| Tmax − Tmean | +0.95 〜 +0.97 | — | 冗長。Tmaxを2回数えているだけ |
| 最高温層の面内温度差 | +0.89 〜 +0.90 | 1.1〜1.5 K (29〜38%) | ほぼ冗長 |
| 最高温層の面内最大勾配 | +0.37 〜 +0.64 | 1.0〜1.8% | 対立するが変動が小さい |
| 全層での面内温度差の最大 | +0.06 〜 −0.10 | 0.75〜1.14 K (4.6〜7.0%) | ほぼ独立 |
| Σn^2（偏り） | +0.15 〜 +0.41 | — | 対立する（現行の3つ目） |

指標の定義:

- `最高温層` = Tmax が乗る z 面
- `面内温度差` = その z 面での max − min（ゴーストセルを除く）
- `面内最大勾配` = その z 面での sqrt((T[i+1,j]-T[i-1,j])^2 + (T[i,j+1]-T[i,j-1])^2)/2 の最大値
- `全層での面内温度差の最大` = 全 z 面について面内温度差を計算した最大値

**注意点:**

- 「全層での面内温度差の最大」は Spearman ≈ 0 で理想的に見えるが、
  この値は k=4〜8 の層（面内幅 15〜16 K）で決まっている
- そこは**旧BCで底面を等温にしたせいで生じている層**であり、新BC（底面断熱）では消える
- **新データで測り直しが必要**
- 計算コストは 90ファイルで 7.9 秒。新データが出たら同じ計算を回すだけ

### 3.13 最適化探索の実測コスト

探索アルゴリズムは多点スタートの最急降下法（`rom_search.jl`）。

- 近傍 = TSVを1本、セル i から j へ移す（16 × 15 = 240通り）
- **400リスタート → 相異なる局所最適が1つだけ**
  - 谷が1つしかない。**GAは不要**で、局所探索で解ける
- Tmax は全1,874,048セルではなく上位20,000セルに限定して評価
  - holdout 69ケースで full 再構成との差は 0.000e+00 K（限定は厳密）

実測時間（シングルスレッド）:

```
ROM 1評価                 0.064 ms
近傍1周（240評価）         15.4 ms
1降下（約40ステップ）       0.62 s
400リスタート              4.1 分      ← N 1水準あたり
N を25点走査               103 分      ← 並列10なら約10分
```

- FVM 1本が330秒なので、**ROMは約500万倍速い**（計算時間比較の数字）
- 現行の `rom_search.jl` は Tmax の最小化のみで、Paretoフロントは作らない
  - フロントは `pareto_and_power.jl` がサンプル済み330設計から非支配集合を取っている
  - 探索ベースのフロントが欲しければ ε制約法（Σn^2 ≤ ε の下でTmax最小化、εを振る）
    10段階 × 3水準 で約2時間

### 3.14 現行のROM評価が測っていないもの

`build_rom.jl` が holdout で測っているのは **Tmax誤差 と 場のL2 のみ**（`holdout_predictions.tsv` の列は
name / split / budget / sum_sq / tmax_fvm / tmax_rom / tmax_count / tmax_cells）。

  - 143モード中24モードしか使っていないので、場のL2が 0.064% でも勾配の誤差はそれより大きい
- 温度勾配を目的関数にするなら、**この誤差を測らずには採用できない**

### 3.16 上面 h の決定（D7）

各条件の熱抵抗（実測 dT / 0.384 W、上面面積 1.2x1.2 mm = 1.44 mm^2）:

| 条件 | h [W/m^2K] | R_total [K/W] | R_境界 = 1/(hA) | R_内部 |
|---|---|---|---|---|
| iso | 無限大 | 39.48 | 0.00 | 39.48 |
| **h151k** | **151,000** | 44.14 | **4.60** | 39.54 |
| h35k | 35,000 | 59.40 | 19.84 | 39.56 |
| h5k | 5,000 | 177.89 | 138.89 | 39.00 |

- **R_内部が4条件すべてで 39.0〜39.6 K/W に揃う**
  - モデルが正しい直列熱回路として振る舞っている証拠。原稿の検証データに使える

**議論は h ではなく熱抵抗 [K/W] で行うこと。**
文献の h は基準面積の定義が曖昧（フィン表面基準かベース面積基準かで2桁違う）ため、
h の値そのものを引用すると誤りやすい。K/W なら意味が一意に定まる。

比較対象:

| 比較対象 | R [K/W] | 出典・確度 |
|---|---|---|
| **本研究 h151k** | **4.60** | — |
| Chen et al. (2025) のパッケージ（h=2,500、13.6x19.6 mm） | **1.50** | **A**（論文本文を取得して確認） |
| 1.2mm熱源の拡散抵抗（銅 k=400） | 1.00 | B（標準式、下記） |
| 1.2mm熱源の拡散抵抗（アルミ k=222） | 1.80 | B |
| 市販ヒートシンク単体 | 0.1 〜 10 | B（Aavid ML26AAG = 10 K/W @200fpm、パワエレ用途 0.1 K/W） |

**拡散抵抗の式**（Muzychka, Yovanovich & Culham 2004 の無次元化 ψ = 4k_1 a R_s と整合）:

```
半無限体・円形熱源
  等温源      : ψ = 1        -> R = 1/(4ka)
  等熱流束源  : ψ = 32/3π²   -> R = 8/(3π²ka)   ← 使用
等価半径 a = sqrt(A/π) = 0.677 mm
```

**結論: h = 151,000 W/m^2K（R_境界 = 4.60 K/W）を採用**

- 「拡散抵抗 1〜1.8 K/W + ヒートシンク 数 K/W」として自然な値
- Chen et al. のパッケージより **3.1倍保守的**（冷却が弱い側）
- h35k（19.8 K/W）は Chen の13倍で過大、h5k（138.9 K/W）は裸のチップ相当、iso は理想化しすぎ

原稿での書き方:

> 上面には有効熱伝達係数 h = 1.51 x 10^5 W/(m^2 K) を課した。これは境界熱抵抗
> R = 4.60 K/W に相当し、1.2 mm 角のダイからスプレッダを経てヒートシンクに至る経路
> （拡散抵抗 約1〜1.8 K/W にヒートシンクの熱抵抗を加えたもの）を単一の境界条件に集約した値である。
> 参考として、Chen et al. (2025) が用いるパッケージ条件は R = 1.50 K/W に相当し、
> 本設定はそれより保守的である。

**却下した根拠（使わないこと）:**

- 「ヒートシンク h = 250〜1000 W/m^2K」は基準面積が不明で原典を特定できなかった
- 文献で確認できた h は フィン表面基準: 自然対流 2〜10、フィン付き自然対流 2.5〜25、強制対流 20〜100 W/m^2K

**新規性への影響:**

- 「同一TSV本数で配置を変えると温度が変わる」こと自体は **2016年に示されている**
- **主張を「配置が効くこと」から「配置空間を探索できること」へ移す**

| | Tavakkoli (2016) | 本研究 |
|---|---|---|
| 配置の表現 | 手作りの4パターン | **16セルの密度マップ（連続パラメータ）** |
| 探索 | なし（4つを比較） | **設計空間全体を探索**（約 4x10^13 通り） |

| 最適性の検証 | 4つの中の最良 | **真の最適の的中を regret で検証** |
| 交換関係 | なし | **Paretoフロント（多目的）** |
| 発熱分布 | 全コア同一電力 | **非対称（ロジック/メモリ、ホットスポット2種）** |

- **Tavakkoli 自身の「最適配置は発熱面積に依存して切り替わる」という発見が、
  本研究の動機になる**（条件ごとに最適が変わるなら、空間を探索できる代理モデルが要る）
- 弱点ではなく、**引用して動機づけに使える先行研究**

### 5.1b TSV本数の扱い

**ROMは1つ。全水準を混ぜて学習する。水準ごとに分けるのは評価の集計だけ。**

| | どうする | 理由 |
|---|---|---|
| モデル | ROMは1つ。全水準を混ぜて学習 | 混ぜても配置は学習できている（N=48固定でSpearman 0.9526） |
| 評価 | 水準ごとに分けて報告 | 混ぜた数字は配置の実力を示さない（§3.10） |
| 最適化 | N を自由に動かす | 1つのROMが内挿する |

- 学習データを水準にする理由は**評価のためだけ**
  - 同じNの設計が複数ないと「本数を固定した比較」が存在しない
  - モデルの作り方は現状と変わらない（`build_rom.jl` は budget で分けずに学習している）
- **本数ごとにROMを分けてはいけない**
  - 各ROMの学習データが1/3（133本）になる
  - 学習曲線より、133本なら誤差 約0.09 K、混ぜた260本なら 0.073〜0.082 K → 悪化する
  - 混ぜて学習しても水準ごとの評価はできるので、分ける利点がない
- **最適化でNを連続に扱ってよいことの検証**（追加FVM不要）
  - {36, 60} で学習 → N=48 を予測 → FVM結果と比較（3水準なら中央を抜く）
  - 聞いているのは「1つのROMが学習していない本数を予測できるか」
  - 通れば連続的なNでの最適化を正当化できる
  - 通らなければ最適化を水準上に限定するか、水準を増やす
  - 既存データでも今すぐ試せる
- **退避先**: 時間が足りなければ N を1水準に絞ってよい
  - 本数はパラメータでなくなるが、Σn^2（偏り＝製造難度）が第2目的として残るので
    「多目的関数によるパラメータ評価」は成立する
  - 図表も主張も、本数の軸を削るだけでそのまま残せる

### 5.5 最適化要件

**目的関数**

- 第1目的: Tmax（文献的に標準）
- 第2目的: TSV本数 N（面積・配線資源のコスト。教科書的で最も正当化しやすい）
  - N = Σμ なので厳密に分かる。予測不要・誤差ゼロ
- 第3目的: 次のいずれか。Day2 に新データで §3.12 の相関を測って決める
  - **確実案**: Σn^2（偏り＝製造難度）。既存コードで動き、330設計から21点の非支配集合が出ている
  - **両方を同時に計算しておくこと**。どちらも温度場とμから計算するだけでコストゼロ。
    片方しか計算しないと、落ちたときに測り直しになる
  - **希望案**: 面内最大勾配（発熱層内）。熱応力・タイミングスキューの観点で文献的正当性が強い
- **禁止**: 温度勾配を Tmax − Tmean や 最高温層の面内温度差 で定義すること
  - Tmax と +0.89〜+0.97 相関し、Paretoフロントが潰れる（§3.12）
- 第3目的の採否基準（**両方**を満たすこと）
  1. 独立性: 水準ごとの Spearman(Tmax, ·) が **|0.7| 未満**（§3.12）
  2. **予測可能性: ROMによる予測誤差が、設計による変動幅より十分小さい**（§3.14）
     - 勾配は場の微分なので、場のL2が小さくても誤差が大きくなりうる
     - 面内最大勾配の変動幅は 1.0〜1.8% しかないので、この基準は厳しい
     - 通らなければ Σn^2 に退避する（μ から直接計算でき、予測誤差ゼロ）

**逐次サンプリング（フロント近傍の局所細密化）**

- **N方向には鋭い膝が無い見込み**（§3.11）
  - Tmax vs N の2階差分は 0.26 K。全変化3 Kに対して小さく、滑らかに逓減しているだけ
  - 膝が出るとしたら (Tmax, 勾配) 平面のほうで、特定のNに紐づくとは限らない
  - **したがって「膝のNで大量に取る」打ち方は狙いが外れる**
- 正しい手順: **μ空間の局所細密化**
  1. 3水準でROMを作る
  2. Paretoフロントを描き、関心領域にある設計 μ* を数個選ぶ
  3. μ* を中心に、TSVを数本動かした摂動を **30本ほど**生成してFVM（約17分）
  4. ROMを作り直し、フロントの形が変わらないことを確認
  5. 必要ならその設計を直接FVMで確認（+8本・約5分）
- 本数の目安

  | 目的 | 本数 | 時間 |
  |---|---|---|
  | フロント近傍でROMの精度を上げる | 30本 | 17分 |
  | その設計をFVMで直接確認 | +8本 | 5分 |
  | そのNを他と同じ「水準」として統計まで出す | 128本 | 1.4時間 |

  - 学習曲線から 200→260本 の改善はほぼゼロ。**全体の密度を上げるのは無駄で、狙った場所を厚くするから効く**
  - 100本以上必要になるのは「最適なTSV本数はNだった」を主要結論にし、
    そのNでも水準内Paretoや配置効果の幅まで報告する場合だけ
- **これができるのは Dirichlet サンプリングだから**
  - LHSはN点セットを丸ごと設計する方式なので、後から足すとLHSでなくなる（§2.8）
  - Dirichlet は独立サンプリングなので、どのNにも何本でもいつでも足せる
- 原稿には「膝の近傍で逐次的に精度を確認した」と書ける（adaptive DOE は確立した方法）

**探索**

- 多点スタートの最急降下法（近傍 = TSV1本をセル間で移動、240通り）
- 400リスタート（既に「1つの局所最適に収束」を確認済みの設定。増やす必要はない）
- **GAは不要**（400リスタートで相異なる局所最適が1つだけ）

**Paretoフロント**

- サンプル済み設計からの非支配集合 + 探索で見つけた最適点を重ねる（既存コードで動く）
- より良いフロントが必要なら ε制約法（10段階 × 3水準 で約2時間）

**Nの扱い**

- 学習は3水準だが、**最適化ではROMでNを1本刻みに走査して連続的なフロントを描く**
- 走査範囲は学習範囲内（N=36〜60）に限る。外挿はしない
- 25点 × 400リスタート = 103分（並列10で約10分）

**最良 vs 最悪の報告**

- 改善量は2通りで報告する
  - uniform比（現行）: -1.29 K

### 5.6 執筆要件

- 境界条件変更の根拠は次の3点で書く
  1. 対流RHSのコード不具合（物理と無関係の実装バグ）
  2. 文献準拠（上面のみ対流、他は断熱は標準的）
  3. 旧設定では温度上昇の66%がPCBで生じ、TSVが原理的に触れない領域だった
  - 「改善量の比が良くなった」は根拠にしない（分母が変わっただけで循環論法になる）
- 新規性の差分を明示する（密度マップ表現も重ね合わせも既出）
  - **Tavakkoli et al. (2016) が同一TSV面積での配置比較を既に行っている**（§3.19）
  - 主張を「配置が効くこと」から「**配置空間を探索できること**」へ移す
  - 差分: 連続パラメータ化 / 代理モデル / 全空間探索 / regret による最適性検証 / Paretoフロント / 非対称発熱
- サンプリングは「混合物実験計画（mixture design）」の枠組みで説明する
- 応答がほぼ線形であることを隠さず書く（それ自体が知見）
- μ → TSV座標 の写像が不連続である点を「今後の課題」として記載する
- **UF1〜UF4 は「アンダーフィル」ではなく「TIM層」と書く**（文献との対応が明確になる、§3.18）
- **パワーマップは「文献値」ではなく「文献範囲内の合成マップ」として主張する**（§3.17）
- 上面 h の根拠は拡散抵抗 + ヒートシンク h（250〜1000 W/m^2K）の積み上げで書く（§3.16）
- **限界として明記するもの**
  - 上部界面もバンプ接合としてモデル化（実装は連続TIM）。TIM置換で uniform比は0.82倍、幅は1.003倍
  - チップ幅が熱拡散長の 2.4倍しかない（文献は20倍）
  - 熱境界抵抗（TBR）を考慮していない
  - チップ平均電力密度が文献より低め（38.4 vs 90〜220 W/cm^2）
  - 発熱面積率 γ = 0.160（実チップは全面に背景電力がある）

  - > As a common practice, we simplify the primary path to dissipate heat into the ambient

    > condition on each surface except the bottom.
  - 冷却する「底面」は1次経路（ヒートスプレッダ・ヒートシンク）側。座標軸が逆向きなだけで本研究と同一構成
